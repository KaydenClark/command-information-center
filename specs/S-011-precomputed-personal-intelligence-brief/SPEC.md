## Outcome

The Intelligence Brief is computed once from existing backend intelligence,
cached with visible freshness, and reused wherever it appears (Dashboard and
Intelligence) without a fresh paid generation call per tab load; when personal
context is configured the brief reflects it rather than feed-only summaries.

## Why It Matters

Every Dashboard load and every Intelligence-tab click currently triggers a live
OpenAI synthesis call, so the operator pays repeatedly for the same content and
the brief is slow. It is also feed-only, so it cannot speak to Kayden's actual
priorities. A precomputed, reused, personally-grounded brief is both cheaper and
more useful, and matches the workspace rule that CIC surfaces existing
intelligence rather than manufacturing it on demand.

## Current Verified State

- `server/intelligence.js` calls `generateOverviewWithOpenAI`
  (`server/openaiSynthesisClient.js`) and stamps `generatedAt` with the current
  time on each request; there is no persisted brief cache.
- `src/main.jsx` (Dashboard) and `src/intelligence.jsx` (Intelligence tab) each
  request the overview independently, so opening the second surface regenerates
  the same content.
- The synthesis prompt is built from the CIC feed and OpenBrain context only; no
  personal profile/context source is wired in.

## Desired Behavior

- The brief is generated by a bounded server-side job (scheduled and/or
  on-demand-with-cooldown), persisted with `generatedAt`, `generatedBy`, and
  source provenance, and served from cache to every surface.
- Opening the Dashboard or Intelligence tab reads the cached brief; a fresh
  generation happens only when the cache is stale past a configured age or an
  explicit refresh is requested.
- When a personal-context source is configured, the brief incorporates it; when
  it is not, the brief degrades honestly to feed-only and says so.
- Freshness (age of the cached brief) is visible; a stale brief is labeled, not
  silently served as current.

## Decisions And Contracts

- The cache is a regenerable derived artifact, not a second canonical memory;
  it never outranks the live feed or OpenBrain.
- Generation stays server-side and bounded; the browser never triggers an
  unbounded or uncooled paid call.
- Personal grounding uses an explicitly configured, in-scope context source;
  absence degrades visibly rather than fabricating personal detail.

## Non-Goals

- Building the personal-context/memory backend itself (CIC consumes it; it is
  owned elsewhere, e.g. OpenBrain / Wiki).
- Redesigning the Intelligence tab layout (owned by S-012).
- Changing the answer/Q&A path beyond letting it reuse the cached brief context.

## Ticket Done Contracts

### TK-001 - Server-Side Precomputed Brief

Done when the brief is generated by a bounded server job, persisted with
provenance and `generatedAt`, served from cache, and regenerated only when stale
past a configured age or explicitly refreshed; fixtures/tests prove cache hit,
stale regeneration, cooldown, and honest degrade when synthesis is unavailable.

### TK-002 - Single Brief Reused Across Surfaces

Done when Dashboard and Intelligence both read the one cached brief (no second
generation on tab switch), proven by a test asserting a single generation call
across both surface reads within the cache window.

### TK-003 - Personal-Context Grounding

Done when an optional configured personal-context source is incorporated into
brief generation, its absence degrades to a visibly feed-only brief, and no
personal detail is fabricated when the source is missing.
