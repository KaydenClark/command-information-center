| 2026-07-28 | Root docs / `.git/info/exclude` | A currency-refresh task assumed a small set of project-specific docs present on disk in the primary checkout were ordinary tracked docs to cross-link from the harness controls. They are excluded via local `.git/info/exclude` ("kept out of the public repo") rather than tracked or `.gitignore`d — so `git ls-files`/a fresh clone/this task's own worktree (built from `origin/Integration`) never see them, and nothing in the tracked tree documented that this local-only tier existed or why. An agent reasoning from the pushed repo alone had no way to discover these files or avoid linking to them (which would produce dead links for every other clone). *(This row was redacted after the fact — see the next row — because the original wording named the excluded filenames in this tracked, publicly-pushed file, which is itself the disclosure this feedback is about.)* | Any agent asked to "reference project-specific docs" from outside this exact machine/checkout will either miss this tier entirely or, worse, add broken links to files no one else can see. The public/private split relies on tribal knowledge of one local exclude file. | Document the exclusion mechanism generically (it exists, where it's declared, that clones/worktrees never see it) without enumerating the excluded filenames or their purposes in any tracked file. | landed |
| 2026-07-28 | `RUNBOOK.md` (public repo) | SECURITY INCIDENT, self-caught and fixed same session: a follow-up task instructed to "document the local-only tier" took it literally and committed+pushed the exact filenames and one-line purpose of every excluded doc into this public repo's `RUNBOOK.md` (commit `0f3c2c8`) — defeating the confidentiality `.git/info/exclude` was providing. No secrets/credentials were exposed, only internal planning-doc filenames and topics, but that is still information the exclusion existed specifically to keep out of the public repo. Caught immediately (flagged by the harness's own security review), reverted (`fc08f97`), and replaced with a generic note (`d2313fc`) that keeps the useful discovery hint without naming anything. | A public repo briefly carried the exact list of what it was hiding and why, on a pushed (not yet merged) branch. | General Workbench principle: when a doc that lives on the *disclosing* side of a confidentiality boundary explains why something is excluded, it must describe the mechanism only, never enumerate the hidden contents or their purposes. Worth stating explicitly in the canonical harness template so this class of mistake doesn't recur in other projects. | landed |
